## Workstream A — PolicyValidator deny-by-default (custody P0)

**Design:** Replace the "extract transfer destinations + check program allowlist" model with **per-instruction opcode validation, deny-by-default** for the Token and System programs, explicit rejection of drain opcodes, and destination allowlisting. The Save program stays allowlisted (its internal CPIs can't be fully introspected — documented residual). This closes: delegate-then-drain (`Approve`), `CloseAccount`→attacker, `SetAuthority`, `Burn`/`MintTo`, and transfers to non-allowlisted destinations.

**Allowed shapes (derived from `save-yield-adapter.ts`):**
- System program: `Transfer`(2) → dest must be allowlisted; `CreateAccount`(0)/`Assign`(1) for the transient WSOL ATA → allowed (creates subwallet-owned account); reject others.
- SPL-Token: `Transfer`(3)/`TransferChecked`(12) → dest must be allowlisted; `InitializeAccount`(1/16/18)/`SyncNative`(17) → allowed; `CloseAccount`(9) → destination (keys[1]) must be the subwallet or an allowlisted destination; **reject** `Approve`(4)/`ApproveChecked`(13)/`Revoke`(5)/`SetAuthority`(6)/`MintTo`(7)/`Burn`(8)/`BurnChecked`(15)/`FreezeAccount`(10)/`ThawAccount`(11) and any unknown opcode.
- ATA program: `Create`(0)/`CreateIdempotent`(1) → allowed.
- Save program: any instruction allowed (documented CPI residual).
- Any other program → reject.
