# SRCLA — Safe, Robust, Cost-Aware Lending Allocation

[![Network: Base](https://img.shields.io/badge/Network-Base_(8453)-0052FF.svg)](https://basescan.org/)
[![Solidity](https://img.shields.io/badge/Solidity-0.8.24-brightgreen.svg)](https://soliditylang.org/)
[![Foundry](https://img.shields.io/badge/Foundry-Testing_%26_Deployment-orange.svg)](https://getfoundry.sh/)
[![TypeScript](https://img.shields.io/badge/TypeScript-Fastify_4-3178C6.svg)](https://fastify.dev/)
[![Prisma](https://img.shields.io/badge/Prisma-5-2D3748.svg)](https://www.prisma.io/)
[![License: UNLICENSED](https://img.shields.io/badge/License-UNLICENSED-lightgrey.svg)](#)

**SRCLA** allocates a pooled USDC ERC-4626 vault across lending venues on **Base (chainId `8453`)** — Compound III,
Aave V3 and Moonwell. It forecasts each venue's supply yield (including how the vault's own deposit moves the
rate), holds a dynamic liquidity reserve, and moves capital only when the forecast edge clears the cost of moving,
inside guardrails the vault contract enforces.

This is the research codebase of the thesis *Navy – Nghiên cứu và thiết kế hệ thống phân bổ tối ưu hóa tài sản
ERC-20 trên các giao thức cho vay phi tập trung*.

> **Status.** The registered evaluation has been run on both sealed eras and returns **`FAIL`**. The paper reports
> that result rather than tuning it away — see [`report/SRCLA-REPORT.md`](report/SRCLA-REPORT.md) and §13 / Appendix F of
> [the paper](docs/research/output/srcla-paper.md).

> **No testnet.** Local development runs against an **Anvil fork of Base mainnet** on `:8545`.

## How it fits together

```
 Base mainnet archive ── pnpm backfill:history ──┐
                                                 ▼
 Anvil fork of Base (:8545) ── collector ──▶ srcla Postgres (:5433)
        ▲                                        │
        │                          forecast → reserve → policy → plan
        │ submitPlan (ALLOCATOR_ROLE)            │
        └───────────────── KeeperExecutor ◀──────┘

 srcla serves GET /v1/* on :3100 (read-only) and operator POSTs on 127.0.0.1:3101
```

- **The contract is the guardrail.** `capBps` / `minIdleBps` / `maxLossBps` are enforced on-chain, and the
  allocator can only move funds between owner-allowlisted adapters — never to an EOA.
- **The service holds the keeper key; its public API cannot move funds.** The public listener is GET-only and
  refuses to boot if a mutating route is registered (paper §10.2).
- **Users sign and pay for their own deposits and redemptions** (paper §2.1) — there is no relayer.

### The algorithm, by paper section

| Section | Topic | Code |
| :--- | :--- | :--- |
| §7 | Return forecasting and calibration | `srcla/src/forecast/`, `srcla/src/policy/steps/forecast.ts` |
| §8.1 | Dynamic liquidity reserve | `srcla/src/policy/steps/reserve.ts`, `srcla/src/reserve/` |
| §8.2 | Allocation enumeration | `srcla/src/policy/steps/optimize.ts` |
| §9.1 | Cost gate | `srcla/src/policy/steps/` |
| §9.2–§9.4 | Reward accounting and harvesting | `srcla/src/rewards/`, `srcla/src/policy/harvest.ts`, `contract/src/reward/` |
| §10.2 | Authority boundary | `srcla/src/http/`, `srcla/src/index.ts` |
| §11 | Evaluation protocol — baselines B0–B5, ablations H1–H7, release gates | `srcla/src/evaluation/` |

The decision itself is `srcla/src/policy/decide.ts`, which runs the steps in `srcla/src/policy/steps/`.

Every tunable is an `SRCLA_*` env var, mapped to its paper section in `srcla/src/config.ts`.

## Running locally

Order matters — each step depends on the one above it.

### 1. Fork Base mainnet

```bash
anvil --fork-url https://mainnet.base.org --code-size-limit 100000
```

The fork inherits every real Base address (USDC, Compound Comet, Aave Pool, Moonwell).

### 2. Deploy the vault

```bash
cd contract
forge build
forge script script/DeployNavyVaultSRCLA.s.sol --fork-url http://127.0.0.1:8545 --broadcast
```

`DeployAndFund.s.sol` deploys the four funded tier vaults that §11.1's fork replay needs; see
[`contract/README.md`](contract/README.md). **Copy the printed addresses into `srcla/.env.anvil`** — they change on
every redeploy.

### 3. Start the database

```bash
cd srcla
docker compose up -d              # srcla on :5433
pnpm install
cp .env.example .env              # then fill in the deployed addresses
pnpm prisma:push
```

### 4. Start the service

```bash
pnpm dev                          # /v1/* on :3100 + the scheduler + the keeper
```

## Running the registered evaluation

```bash
cd srcla
DATABASE_URL=… pnpm backfill:history     # ~45 min, resumable — hourly Base venue state since 2024-03-15
DATABASE_URL=… pnpm phase4:freeze        # ~10 min -> config/registered-artifact.json
DATABASE_URL=… pnpm phase4:run           # 3-4 hours and silent; writes report/ (report, figures, chart data)
DATABASE_URL=… pnpm evaluation:verify ../evaluation-heldout-c.json
pnpm figures:render --png                # redraw report/figures/ from report/chart/ in seconds (PNG needs Chrome)
```

§11.1's fork replay additionally needs the fork, four per-tier vaults and the `SRCLA_FORK_REPLAY_*` variables —
see [`CLAUDE.md`](CLAUDE.md#running-the-experiment). The data split is sealed in `srcla/src/evaluation/eras.ts`.

## Testing

```bash
cd srcla    && pnpm test:unit        # unit suite (use this, not a raw `npx jest`)
cd srcla    && pnpm test             # unit + integration (integration needs Postgres)
cd contract && forge test            # unit + fuzz/invariant + Base-fork tests
```

`cd srcla && source .env.anvil && pnpm phase1:check` runs one real decision cycle, and the keeper execution of
its plan, against the fork.

## Security

- **Audit.** `NavyVaultSRCLA` and its adapters were audited — see
  [`contract/audit/AUDIT-REPORT.md`](contract/audit/AUDIT-REPORT.md), the per-area findings in
  `contract/audit/2026-08-12-audit/`, and the release evidence in
  `contract/audit/RELEASE-EVIDENCE-2026-08-14.md`. The Phase 2 changes made after the audit are recorded in
  `contract/audit/2026-09-07-phase2-changes.md` and are not yet re-audited.
- **Not production-ready.** Real funds require the gates in [`docs/PRODUCTION.md`](docs/PRODUCTION.md): an
  independent audit, owner → multisig/timelock, and KMS/HSM key custody.
